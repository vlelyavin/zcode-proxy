# zcode-proxy

[README in English](README.md)

Локальный релей для тех, у кого есть триальные кредиты ZCode (старт-план), а рабочим инструментам нужен обычный API-ключ. Прокси принимает запросы по протоколам OpenAI и Anthropic и перенаправляет их в нативный модельный эндпоинт ZCode через ваш аккаунт. Это позволяет запускать Hermes, OpenCode или просто слать curl-запросы, расходуя триальный баланс вместо платных токенов.

## Возможности

- Совместимость с OpenAI API (`/v1/chat/completions`, стриминг, вызовы инструментов) и сквозной эндпоинт `/v1/messages` для клиентов Anthropic.
- Запросы к `zcode.z.ai` отправляются по тому же пути Anthropic, что использует официальный клиент.
- Авторизация через локальные учетные данные ZCode: читаются при старте и обновляются при получении `401`. В репозитории нет никаких токенов.
- Стриминг вызовов инструментов и рассуждений (reasoning) обратно в виде дельт OpenAI.
- Автоматический однократный повтор при ошибках `429` и `5xx`, обновление токена при `401`.
- Ноль npm-зависимостей: используется только стандартная библиотека Node.js.

## Чем проект не является

- Не является официальным продуктом z.ai и никак с ними не связан.
- Это не публичный хостинг: сервис работает локально и на ваших учетных данных.
- Это не база общих ключей: в репозитории нет никаких приватных данных.

## Как это устроено и ограничения

Прокси использует триальный эндпоинт в обход официального клиента. Шлюз проверяет схожесть входящего запроса с вызовами из оригинального окружения; если проверка не проходит, возвращается ошибка `405 code 3012 unusual activity`. Для обхода этой проверки релей отправляет системную преамбулу окружения, встраивая ваш системный промпт в её последний блок. 

Сервис z.ai может изменить эти правила в любой момент. Параллельные запросы с одного аккаунта повышают риск блокировки, поэтому по умолчанию прокси держит не более двух активных запросов. Заблокированные запросы не списывают баланс, но повторять их во время блокировки бессмысленно.

Срок действия промо-кредитов ограничен. Проверить текущий остаток можно командой:
```bash
curl -sS http://127.0.0.1:18960/status -H "authorization: Bearer <localKey>"
```

## Требования

- Node.js 22.5+ (для авторизации требуется встроенный модуль `node:sqlite`).
- Linux или macOS (на Windows - через WSL, помощник входа написан на bash).
- Авторизованный клиент ZCode на целевой машине: должен присутствовать файл `~/.zcode/v2/credentials.json`. Без него релей работать не будет.
- Наличие триальных кредитов на аккаунте. Для платных API-ключей open-platform этот релей не нужен.

## Установка

```bash
git clone https://github.com/vlelyavin/zcode-proxy.git
cd zcode-proxy
npm i -g zcode-app-cli     # CLI официального клиента, нужен только для первичного входа
./bin/zcode-login          # Выведет ссылку для авторизации; откройте её в браузере, где выполнен вход в chat.z.ai
node src/cli.js setup      # Создаст config.json со случайным локальным ключом
node src/cli.js check      # Проверит учетные данные, доступность эндпоинта и баланс
node src/cli.js run
```

Команда `npm install` внутри самого репозитория не требуется. По умолчанию сервер слушает адрес `127.0.0.1:18960`.

Проверка работоспособности:
```bash
curl -sS http://127.0.0.1:18960/health
```

## Использование

```bash
# Пример запроса через любой OpenAI-совместимый клиент
curl -sS http://127.0.0.1:18960/v1/chat/completions \
  -H "authorization: Bearer $(jq -r .localKey config.json)" \
  -H "content-type: application/json" \
  -d '{"model":"zcode","stream":true,"messages":[{"role":"user","content":"ping"}]}'
```

Доступные модели: `zcode` (GLM-5.3-Flash) и `zcode-5.3` (GLM-5.3). Алиасы `glm-5.3-flash` и `glm-5.3` также поддерживаются.

Для Hermes: настройте кастомного провайдера с базовым URL `http://127.0.0.1:18960/v1`, укажите ваш `localKey` и используйте модель `zcode` или `zcode-5.3`.

## Конфигурация

Файл конфигурации опционален. Пример структуры можно посмотреть в `config.example.json`.

```bash
ZCODE_PROXY_CONFIG=./config.json node src/cli.js run
```

| Параметр | Описание |
| --- | --- |
| `bind` / `port` | Адрес и порт сервера (по умолчанию `127.0.0.1:18960`) |
| `localKey` | Секретный ключ для доступа к прокси; при несовпадении возвращается 401 |
| `models` | Маппинг локальных алиасов на идентификаторы моделей апстрима |
| `maxInflight` | Максимальное количество одновременных запросов к апстриму (по умолчанию 2) |
| `effort` | Значение `output_config.effort` по умолчанию, если клиент не передал `reasoning_effort` |
| `credentialsPath` / `telemetryPath` | Пути к файлам токенов и идентификатора устройства |
| `appVersion` | Версия приложения, передаваемая в заголовках отпечатка клиента |

Переменные окружения: `ZCODE_PROXY_BIND`, `ZCODE_PROXY_PORT`, `ZCODE_PROXY_KEY`, `ZCODE_PROXY_EFFORT`, `ZCODE_PROXY_MAX_INFLIGHT`, `ZCODE_PROXY_CONFIG`.

## Устранение неполадок

| Ошибка / Симптом | Причина и решение |
| --- | --- |
| `405 {"code":3012}` | Структура запроса не совпадает с ожидаемой. Не изменяйте первые системные блоки; пользовательский текст должен передаваться в третьем блоке (см. `docs/architecture.md`). |
| `502 Bad Gateway` | Временный сбой на стороне шлюза при валидном запросе. Прокси уже выполнил один автоматический повтор; обычно запрос проходит со следующей попытки. |
| `401 VERIFY_*` | Истёк срок действия JWT. Выполните `./bin/zcode-login` и перезапустите сервис. |
| `cannot read ZCode credentials` | Сессия не найдена либо файл учетных данных зашифрован другим пользователем или ключом. |
| Пустые ответы от модели | Слишком маленькое значение `max_tokens`: весь лимит уходит на блок рассуждений (reasoning). |

Ошибка `401`, возвращаемая самим прокси, означает, что передан неверный `localKey`.
