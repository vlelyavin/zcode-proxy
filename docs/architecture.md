# Architecture

## Поток

```
клиент (Hermes / opencode / curl)
   |  POST /v1/chat/completions      (OpenAI wire, SSE)
   v
zcode-proxy  (этот репозиторий)
   |  POST https://zcode.z.ai/api/v1/zcode-plan/anthropic/v1/messages
   |  (Anthropic wire, SSE, заголовки отпечатка клиента, JWT в Authorization + x-api-key)
   v
релей ZCode -> модель GLM-5.3 / GLM-5.3-Flash, списание с start-plan бакета аккаунта
```

Релей не запускает приложение и не водит мышью по интерфейсу. Он говорит с тем же
модельным эндпоинтом, что и клиент, поэтому инструменты и стриминг проходят целиком.

## Почему anthropic-wire, а не openai

У апстрима есть и `/api/v1/zcode-plan/chat/completions`, но сам клиент ходит на
anthropic-путь, и он лучше проверен на предмет подсказок/thinking. Наружу релей
отдаёт OpenAI (нужен Hermes и большинству тулинга) и пасс-through `/v1/messages`
для anthropic-клиентов.

## Что подписывается, а что нет

Клиент подписывает бизнес-вызовы (`X-Client-Ts/Sig/Nonce/Pow`, Ed25519 + PoW) — баланс,
конфиги агента. Три модельных пути клиент шлёт **без подписи**:

- `/api/v1/zcode-plan/anthropic/v1/messages`
- `/api/v1/zcode-plan/chat/completions`
- `/api/v1/off-peak/anthropic/v1/messages`

Поэтому в релее нет ни Ed25519, ни PoW, ни хендшейка — только заголовки отпечатка
(`user-agent`, `x-os-*`, `x-zcode-*`, `device_mid` в `metadata.user_id`).

## Правило формы system (главная засада)

Риск-контроль шлюза отвечает `405 {"code":3012,"msg":"request has been blocked due to unusual activity"}`
на запрос, у которого `system` не похож на харнесс:

- должно быть ровно **3 блока**, первый дословно `You are ZCode, an interactive coding agent`;
- чужой системный текст допустим только **внутри третьего блока**; лишний четвёртый блок — 3012;
- без system или с коротким выдуманным system — 3012; пустой наполнитель без преамбулы — 502.

`assets/harness-system.json` — снятая у клиента преамбула. `mergeSystem()` вливает
системный промпт вызывающей стороны в последний блок и никогда не добавляет четвёртый.
Правка преамбулы «для красоты» ломает совместимость.

## Учёт токенов

Списание идёт с бакетов аккаунта (`model:glm-5.3-flash`, `model:glm-5.3`), метрика — сумма
входа и выхода, кеш не бесплатен. Смотреть остаток: `GET /status`. Бакеты разных моделей
тратятся независимо и истекают по сроку промо.

## Конкурентность

`maxInflight` (по умолчанию 2) с очередью. Аккаунт общий с приложением: гнать десяток
параллельных запросов — верный способ поймать 429/3012.

## Отказы

- `401` апстрима — JWT протух: релей перечитывает креды и повторяет один раз; если не помогло, надо перелогиниться
- `429`/`5xx` — один ретрай через 2 с
- `3012` — форма запроса; списаний не было, повторять безопасно
